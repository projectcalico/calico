11 Nov 2026

#### Bug fixes

- Fixes a Felix panic when a malformed (empty) member is present in a NetworkSet used by the nftables dataplane; the member is now ignored with a warning. [calico 14558](https://github.com/projectcalico/calico/pull/14558) (@caseydavenport)
- KubeControllersConfiguration logSeverityScreen now accepts Trace and rejects None, which kube-controllers never supported. [calico 14553](https://github.com/projectcalico/calico/pull/14553) (@caseydavenport)
- A slow or stalled flow stream client no longer blocks Goldmane flow ingestion. [calico 14553](https://github.com/projectcalico/calico/pull/14553) (@caseydavenport)
- CI: fix e2e lanes on release-v3.32 that failed before running tests (kind pull secret, flannel migration modprobe, rancher/k8s-beta version keywords, EKS pod CIDR overlap, stale RHEL 8 AMI). [calico 14534](https://github.com/projectcalico/calico/pull/14534) (@lwr20)
- Fixes nftables-specific Felix configuration (allow and deny actions, mark mask, and refresh interval) being ignored on clusters using the default nftables mode of Auto. [calico 14482](https://github.com/projectcalico/calico/pull/14482) (@caseydavenport)
- Fix Goldmane counting a node's flow statistics twice when Felix reconnects to it. [calico 14482](https://github.com/projectcalico/calico/pull/14482) (@caseydavenport)
- Fixed BGPConfiguration, BGPPeer and BGPFilter rejecting 4-byte AS numbers above 2147483647. [calico 14482](https://github.com/projectcalico/calico/pull/14482) (@caseydavenport)
- Fixes an issue where a pod could lose its IP address to another pod after the container runtime retried sandbox creation and left a stale CNI ADD running, including under Multus. [calico 14482](https://github.com/projectcalico/calico/pull/14482) (@caseydavenport)
- Fixes the IPAM garbage collector never releasing IPs left behind by a pod's earlier sandboxes while the pod has not yet reported an IP, which could exhaust small IP pools such as those used by Multus secondary networks. [calico 14482](https://github.com/projectcalico/calico/pull/14482) (@caseydavenport)
- The IPAM garbage collector now releases leaked IPs of any pod in the Succeeded or Failed phase, not only of evicted pods. [calico 14482](https://github.com/projectcalico/calico/pull/14482) (@caseydavenport)
- Fixes calico-node not assigning or releasing a node's IPIP, VXLAN, or WireGuard tunnel address when an IP pool's nodeSelector changes, which previously needed a calico-node restart. [calico 14482](https://github.com/projectcalico/calico/pull/14482) (@caseydavenport)
- Fixes IP pool deletion hanging until calico-node restarts when a node's IPIP, VXLAN, or WireGuard tunnel address is in the pool. [calico 14482](https://github.com/projectcalico/calico/pull/14482) (@caseydavenport)
- Fixes a leaked IP address, and an IPAM block that could never be released, when a KubeVirt VM is deleted while it is stopped. [calico 14482](https://github.com/projectcalico/calico/pull/14482) (@caseydavenport)
- FelixConfiguration now rejects malformed BPF conntrack timeout values such as `1msms` or `ms`; Felix previously ignored them and kept the default.  eBPF: new "Dropped by workload RPF check" counter for packets with a spoofed source; Felix no longer logs an error about the netkit probe device at startup. [calico 14451](https://github.com/projectcalico/calico/pull/14451) (@marvin-tigera)
- Fix calico-node failing to start on nodes whose kernel is built without CONFIG_SECURITYFS.  eBPF: a pod reaching itself through a service is policed by its own ingress policy again. [calico 14439](https://github.com/projectcalico/calico/pull/14439) (@marvin-tigera)

#### Other changes

- Calico LB ipam in RequestedServicesOnly mode only considers Service to be managed by Calico if either spec.LoadBalancerClass == Calico or if explicitly requested via Calico annotation. Calico LB IPAM no longer considered services with only spec.LoadBalanacerIP to be Calico managed [calico 14568](https://github.com/projectcalico/calico/pull/14568) (@MichalFupso)
- Fix Felix never reporting dataplane in-sync when a workload interface was deleted during its first resync after startup, which made new pods on the node wait out the full CNI policy_setup_timeout_seconds. [calico 14515](https://github.com/projectcalico/calico/pull/14515) (@fasaxc)
- With flexVolumePath set to None, a flexvolume driver already installed in the provider's default plugin directory is now updated on upgrade.  A driver installed at a custom path before switching to None must be removed manually on each node (`rm -rf <custom path>/nodeagent~uds`), after draining any pods that mount `nodeagent/uds`. [calico 14508](https://github.com/projectcalico/calico/pull/14508) (@rene-dekker)
- Fixed a stored policy with a descending port range (for example 9000:8000) blocking the sync of every policy of that type; Felix now ignores only the invalid policy.  Fix leaked QoS bandwidth IFB devices (`bwcali*`) when a pod is deleted while calico-node is restarting, and fix egress bandwidth limits not being enforced for a pod that reuses a leaked device. [calico 14493](https://github.com/projectcalico/calico/pull/14493) (@marvin-tigera)
- Selectors with parentheses nested more than 100 deep are now rejected. [calico 14473](https://github.com/projectcalico/calico/pull/14473) (@fasaxc)
- Calico now validates selectors and service account names in policies written directly to the projectcalico.org/v3 CRDs. [calico 14473](https://github.com/projectcalico/calico/pull/14473) (@fasaxc)
- Calico's `istio-ztunnel` images are now built using `cargo-auditable`, which embeds dependency information directly into the istio binary. This allows vulnerability scanning tools like Trivy to analyze Calico's Istio builds and report vunlerabilities. [calico 14457](https://github.com/projectcalico/calico/pull/14457) (@danudey)
- By default, skip Submariner's vx-submariner interfaces in IP auto-detection. [calico 14421](https://github.com/projectcalico/calico/pull/14421) (@caseydavenport)
- * eBPF: conntrack map autoscaling (DoubleIfFull) now doubles only the IP family whose map is more than 80% full. Grown sizes are recorded per family in /var/lib/calico/bpf_ct4_map_size and bpf_ct6_map_size. * Felix copies BPF maps faster when it resizes them, such as when the eBPF conntrack table grows. * eBPF conntrack metrics now carry an ip_version label, so IPv4 and IPv6 no longer overwrite each other on dual-stack nodes. New felix_bpf_conntrack_max_entries metric reports the conntrack table capacity. felix_bpf_conntrack_cleaned_total now counts cleaned entries instead of visited ones, and a failing BPF conntrack cleaner no longer crashes the conntrack scanner. * Fixed calico-node restarts in eBPF mode resizing BPF maps to their defaults and back, which could crash the init container when the conntrack table held more entries than the default size. [calico 14410](https://github.com/projectcalico/calico/pull/14410) (@tomastigera)
